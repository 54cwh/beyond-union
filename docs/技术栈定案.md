# 北域绿联 · 技术栈定案

> 决策原则：**AI 熟悉不犯错 + 打包简单 + 效果好**
> 5 人全用 AI 写代码，选型只看 AI 生成质量与稳定性
> 模块化 + 契约测试：AI 很容易乱改公共接口，必须焊死防 5 人互相踩踏

---

## 整体架构

```
              浏览器窗口（pywebview 或默认浏览器）
   ┌───────────────────┼───────────────────┐
 p1 运营工作台  p2 发电预测  p3 风光储优化  p4 绿电入市  p5 决策政策  p6 经营成效
   └───────────────────┼───────────────────┘
     Vue 3（本地引入，无构建）+ ECharts（本地文件）+ 全局 AI Copilot 壳
        └─ data/demo/*.json  演示模拟数据（天气/发电/储能/市场/收益，全链路自洽）

数据管线（打包前离线执行）：
  真实 CSV/Excel（如有）→ pandas 清洗 → data/*.json
  无真实数据 → A 造模拟数据集 data/demo/*.json（需求示例数字可直接用）
```

- **无后端**：纯前端 + JSON，本地运行，无服务器
- **产品形态**：新能源经营决策工作台（需求 V2.0），6 页覆盖 12 页需求功能（详见 `docs/分工说明.md` 页面结构）
- **AI 为模拟**：AI 副驾驶/可信 AI 八要素由预置问答库 + 数据实现，非真模型
- **打包**：PyInstaller 打成单 EXE，数据以 JSON 随包内置

## 前端技术栈

| 层 | 选择 | AI 熟悉度 | 效果 | 说明 |
|----|------|----------|------|------|
| 样式 | **Tailwind CSS v3**（静态预编译） | ★★★ 语料海量 | 现代美观、统一 | **锁 v3**（v4 语法不同易让 AI 翻车）；standalone CLI 编译成 `assets/tailwind.css`，**运行时零依赖** |
| JS 框架 | **Vue 3 全局版 · Options API** | ★★★ 中文生态极强 | 响应式交互、写法统一 | `vue.global.js` 本地 script，**无构建**；**禁 `setup()`、禁 `import Vue`**（全局版标配写法，AI 最不易错） |
| 图表 | **ECharts** | ★★★ 中文项目标配 | 图表种类全、联动成熟 | 本地单文件，离线可用 |
| 数据 | **data/demo/\*.json** + fetch | ★★★ | 纯前端原生形态 | 演示模拟数据（A 产出，全链路自洽）|
| 交互查询 | 前端筛选 + 聚合（A 的计算层）| ★★★ | 毫秒级 | 各页决策交互（预测/优化/交易/任务）|

### 锁死细则（防 AI 翻车）
1. **Tailwind 锁 v3.4**：v3/v4 语法不兼容（config 方式、CLI 参数不同），AI 语料以 v3 为主，锁死 v3 消除编译错误
2. **Vue 写法锁 Options API**：`Vue.createApp({ data(){}, computed:{}, methods:{} })`；**禁止 `setup()`、禁止 `import Vue`、禁止 SFC（.vue）代码**——AI 生成 Composition/SFC 时在全局版下必崩
3. **纯函数模块锁 ESM**：`export` + `<script type="module">`；filter.js / format.js **互不 import**（自包含，防路径写错）
4. **Tailwind content 扫描铁律**：统一 `content: ["pages/*.html", "assets/js/*.js", "template.html"]`；**任何人改页面 class 后必须重跑编译脚本**（否则新 class 静默缺样式，不报错）
5. Python 统一 **3.12.x**、Node 统一 **18+**

### 每页启动流程（锁死，6 页照抄）
**架构决策：第三方库用经典脚本挂全局；自己的代码统一 ESM。**
```
1. <link>  tailwind.css → common.css              （样式）
2. <script src> vue.global.js → echarts.min.js     （库，经典脚本，全局 Vue/echarts）
3. <nav id="site-nav"></nav>                        （导航占位，common.js 注入）
4. <div id="app"></div>                             （页面 Vue 挂载点）
5. <script type="module">                           （页面逻辑：import + createApp）
   import { Nav, Data } from '../assets/js/common.js'
   import { ... } from '../assets/js/filter.js'    // 计算层（A 提供），按需 import
   import { ... } from '../assets/js/chart-view.js' // 图表组件（B 提供），按需 import
   Nav.render()                     // 从 location.pathname 自动高亮当前页，不传参
   Vue.createApp({ ... }).mount('#app')  // Options API
```
- 模块脚本天然延迟执行 → DOM 和全局 Vue/echarts 已就绪，无加载顺序 bug
- **common.js 职责**：只做基础设施（Nav.render / Data.load / 通用工具），**不创建 Vue app**
- **页面职责**：自己的 Vue app + ECharts 实例 + 业务逻辑，**不往 common.js 塞东西**
- 页面间数据**每页独立加载**（各页可能负责不同数据类型，本来就是正确设计）；Data 缓存仅单页内有效

### 版本锁定表（精确到防 AI 用错 API）
| 组件 | 锁定 | 理由 |
|------|------|------|
| Python | **3.12.x** | AI 语料最足、生态兼容；本机 3.14 可开发，打包/发布统一 3.12 |
| Vue | **3.4.x**（unpkg 精确文件）| 3.5 新增 API，AI 语料以 3.2-3.4 为主 |
| ECharts | **5.5.x**（jsdelivr 精确文件）| 4→5 改 API 是 AI 高频翻车点 |
| Tailwind | **3.4.x** standalone CLI | 避开 v4 语法分裂 |
| pandas | **2.2.x** | AI 语料最熟区间 |
| pywebview | **5.x** | 成熟稳定 |
| pyinstaller | **6.x** | 当前主流 |
| playwright | **1.4x**（`==` 精确）| API 稳定，锁死防漂移 |
| pytest / pytest-playwright | **8.x / 0.5x** | 配套锁 |

> 锁定机制：Python 依赖用 `pyproject.toml` + `uv.lock`（`uv add` 自动锁）；前端资产用 `assets/vendor/VERSIONS.md` 记录精确版本 + 下载 URL（vendor 文件带版本号入库，防 CDN 漂移）

### 字体决策（Inter + 系统中文栈）
- **西文/数字用 Inter**（本地 woff2，assets/fonts/）：现代数据 UI 标准、tabular 等宽数字对齐工整、AI 最熟、单 weight 十几 KB
- **中文用系统字体栈**（Win=微软雅黑 / macOS=苹方 / Linux=Noto Sans CJK SC）：中文字体无法打包（体积/版权），靠系统最稳
- 弃用 MASTER.md 默认的 Fira 系（Google Fonts CDN 离线会失效；Fira Code 代码感不适合评委受众）
- 变量：`--font-body` / `--font-heading` 定义于 common.css；数字对齐用 `.tabular` class

> 关键取舍：React 虽全球语料略多，但在"无构建 + 离线"约束下非主流用法，AI 生成不稳；**Vue 3 全局版是此约束下 AI 最熟的形态**。

## 数据管线

> **状态：无真实数据 → 用 A 造模拟数据集（data/demo/*.json）；真实数据到位后 pandas ETL 替换。**

### 模拟数据集（当前阶段，A 职责）
- 造一套**全链路自洽**的演示数据（呼应需求示例数字）：天气（风速/温度/辐照）→ 发电预测 → 储能状态 → 市场行情 → 收益/偏差 → 政策/任务/案例
- 需求文档里的示例数字（128.6MWh、SOC 64%、72%/28% 等）可直接用作种子值
- 各页基于模拟数据开发，真实数据替换只改数据源

### 数据架构（已定）
- **数据用 JSON**：`data/*.json` 随包内置，前端 fetch 加载，无需服务器、无需数据库引擎
- **清洗/转换用 pandas**：真实 CSV/Excel → pandas 处理 → 输出 JSON（打包前离线执行）
- **数据多样性 + 可扩充性**：不同类型的数据可放多个文件，不强行合并成一张大表
- **岗责分离**：数据处理（A：ETL/契约/质量校验）与数据展示（B：统一图表组件）分人负责，防止加工错误被展示掩盖

### 待定项（真实数据到手后确定）
- 具体有哪些真实数据集、各自多少表/行/列
- 字段名、字段类型、哪些字段可筛选/可聚合
- 是否需要跨表分析（若需要，pandas 定制处理）
- 是否含图片/非表格类数据

## GUI / 网页双模式

**核心理解：GUI 只是"网页的壳"，页面代码只有一份。**

```
唯一代码库 = 纯网页（HTML/Vue/ECharts/JSON）
                │
        ┌───────┴────────┐
   打包成 EXE         浏览器里直接打开
  pywebview 壳住       (开发预览 / 网页形态)
    = GUI 窗口          = 网页
```

| 形态 | 怎么打开 | 验收人 |
|------|---------|--------|
| **GUI 窗口**（EXE 默认）| pywebview 嵌入原生窗口 | **Windows 成员真机双击验收**（WebView2，Wine 不可验）|
| **网页形态**（EXE `--web` 兜底）| 启动本地服务 + 自动开默认浏览器 | **Linux/Wine 负责人验收**（Wine 调系统浏览器，可靠）|
| **开发预览** | `uv run python -m http.server 8000` 浏览器直开 | 所有人随时测 |

- 启动参数 `--mode gui/web` 切换，两形态共用同一份页面代码，无两套维护
- **验收分工（已定）**：Linux 负责人 = `--web` 模式全功能验收（打包 EXE + 浏览器回归）；Windows 成员 = GUI 窗口真机验收。两边各验各的，互不依赖
- **WebView2 只在"Windows 打包产物"这一环出现**：
  - Linux 本机 pywebview 用 **WebKitGTK**（非 WebView2）
  - Windows EXE 的 GUI 才依赖 WebView2 → 真验证在 Windows 上
  - Wine 下模拟 WebView2 **不可靠** → 切 `--web` 模式照样完整验收
- 结论：**GUI 有风险兜底，web 永不翻车**

> **关于 Wine 与 WebView2 的调研结论（2026）**：微软官方明确不支持 Wine（WebView2Feedback #3127 标 priority-low，近期不解决）；社区 workaround（Bottles+Proton GE+手动装 Edge）可装但**白屏率高、版本敏感**；winetricks 无稳定 verb。故 GUI 验收**只认真 Windows**。

## 测试

**设计约束：模块化 + 故障隔离（人多，最怕一环出问题；bug 要能精确定位到函数）。**
**双工具链：JS 函数用 Vitest（Node），Python/E2E 用 pytest + Playwright，均交由 AI 配置。**

### 模块化约定（强制）
```
assets/js/common.js       # 基础设施: 导航 / Data 加载（E 维护）✅ 已落地
assets/js/chart-view.js   # 统一图表展示: ECharts 生命周期与渲染（B 展示岗维护，接口由 B 设计）✅ 已落地
assets/js/filter.js       # 数据计算: 筛选/聚合/统计/图表适配（A 数据岗维护，接口由 A 设计）✅ 已落地
assets/js/format.js       # 数据计算: 数字/日期格式化（A 数据岗维护，接口由 A 设计）✅ 已落地
assets/js/ai-card.js      # 可信 AI 八要素卡片（B 展示岗维护，跨页组件）→ ⏳ 创建
assets/js/ai-qa.js        # AI 问答库: 预置问答 + 关键词匹配（E 集成岗维护）→ ⏳ 创建
assets/js/copilot.js      # 全局 AI 副驾驶壳: 右侧固定面板（E 集成岗维护）→ ⏳ 创建
规则：所有计算逻辑放数据计算层（filter/format，A 维护），禁止写死在页面/Vue 组件里
```

**全局组件接入机制（防 5 人互相踩，已定）**：
- **Copilot 壳 / AI 问答库由 E 在 common.js 统一注入**，页面**不需要改任何 markup/script**——common.js 挂载后自动初始化右侧 AI 面板。这样 6 页不用各自接入，E 单点维护。
- **可信 AI 卡片（ai-card.js）由 B 提供组件**，页面在需要展示"AI 建议"的地方调用它（模板示范用法）。C/D 页面若用到，照模板调 B 的组件，不自己写卡片。
- **演示模式入口**：B 在 p1 放"开始演示"按钮，调 E 定义的全局 API（`window.__demo.start()` 之类，E 定义签名）；E 在 common.js 里实现。
- 规则：**全局 UI 组件只由 E（壳）或 B（卡片）提供，页面是消费者**，不在页面里自建。
> 骨架中的 filter.js / chart-view.js 是可工作的**参考实现**，具体 API 设计由 A/B 各自决定，可重构。
> **领域自治**：各领域负责人（A=数据/B=展示/E=基础设施）对其领域文件有完全决定权，不需逐次审批；仅**接口变更**（函数签名/字段/导出）须同步文档并通知消费方。

### 三层测试体系（够用为止，不追求完整）
| 层 | 工具 | 抓什么 | 谁跑 |
|----|------|--------|------|
| 1. **函数单测** | **Vitest**（Node） | 每个纯函数返回值精确断言 → **定位 bug 到函数** | 各模块本人 |
| 2. **模块 E2E + 共享契约** | **Playwright (Python) + pytest** | 页面行为 + 导航/资产/数据字段跨模块一致 | 各模块本人 + 共享改动后必跑 |
| 3. **打包回归** | 起 EXE → 端口探测 + 截图 | 打包产物完整性 | 角色 E |

> **共享契约测试（重要，防 AI 乱改）**：`tests/test_contract.py` 焊死 3 个公共接口 ——
> ① 数据字段：实际 JSON 符合 A 的 `data/CONTRACT.md` 契约（谁改字段谁先红，别人页面不静默变空）
> ② 共享资产：每页引用的 `common.js`/`tailwind.css`/vendor 文件存在且路径有效
> ③ 导航：逐页点击导航能到达目标页

```
目录：
  assets/js/__tests__/  # Vitest 单测（纯函数模块）
  tests/test_contract.py      # 共享契约测试
  tests/test_p1.py … test_p6.py  # 每人模块：E2E 行为测试
```

### 故障定位流程
全站回归红 → 契约测试定位到模块（公共接口被谁改了）→ 只找该模块成员 → 跑 Vitest 单测定位到函数 → AI 修复 → 重跑全绿。**每一层把问题缩小一圈。**

### Node 工具链（新增）
| 工具 | 用途 |
|------|------|
| Node 18+ | Vitest 运行环境 |
| `vitest` | JS 纯函数单测 |

> JS 单测定位 bug 对 AI 尤为关键：失败断言给出"函数 + 入参 + 期望值"，AI 直接改目标函数。工具链由各人 AI 自行 `npm install` 配置。

## 依赖清单（锁死，防各 AI 私加包）

**Python 依赖统一用 `uv` 管理**。`uv` 替代 pip+venv，一个命令装环境 + 锁版本，跨平台一致，AI 非常熟。

| uv 命令 | 作用 |
|---------|------|
| `uv python install 3.12` | 装指定 Python 版本 |
| `uv sync` | 按 pyproject.toml 创建环境并安装全部依赖 |
| `uv add <pkg>` | 加依赖（自动更新锁文件）|
| `uv run <cmd>` | 在项目环境里跑命令（`uv run pytest` / `uv run python app.py`）|
| `uv.lock` | 锁文件（等同 package-lock.json，保证全员一致）|

### 1. Python 运行时依赖（进 EXE）
| 包 | 版本 | 用途 |
|----|------|------|
| `pywebview` | ~5.x | 内嵌窗口 |
| `bottle` | ~0.13 | pywebview 内置服务器依赖 |

### 2. Python 开发/测试依赖（不进 EXE）
| 包 | 版本 | 用途 |
|----|------|------|
| `pandas` | 2.2.x | 数据 ETL |
| `openpyxl` | 3.x | 读 xlsx |
| `pyinstaller` | 6.x | 打包（构建期）|
