**时间尺度切换：24H / 48H / 7D**

| 档位 | 行为 | 数据不足时处理 |

### 3. 预测风险时间轴

**需求：** 绿（低风险）/ 黄（波动加大）/ 橙（预测不确定性高）三档时间条。

示例：14:00–17:00 黄色 = 风速骤降，预测波动加大。

#### 3.1 数据方案

**推荐方案：A 层提供风险分级结果**

向 A 提需求，在计算层增加：

```js
classifyRisk(forecast, weather)
```

返回结构建议：

```js
[
  {
    start_time: '14:00',
    end_time: '17:00',
    level: 'mid',
    reason_code: 'wind_speed_drop',
    reason_text: '风速骤降，预测波动加大'
  }
]
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `start_time` | string | 风险开始时间 |
| `end_time` | string | 风险结束时间 |
| `level` | enum | `low / mid / high` |
| `reason_code` | enum | 风险原因编码 |
| `reason_text` | string | 页面 hover 直接展示文案 |

#### 3.2 兜底方案：前端临时规则配置化

A 未提供前，页面可使用临时规则，但阈值必须抽到配置常量，禁止散落在组件逻辑中。

```js
const RISK_RULES = {
  high: { bandwidthPct: 15, label: '预测不确定性高' },
  mid: { bandwidthPct: 10, label: '波动加大' },
  low: { label: '低风险' }
};
```

临时判断规则：

- 置信区间带宽占比 ≥ 15%：橙色（high）
- 置信区间带宽占比 ≥ 10%：黄色（mid）
- 其他：绿色（low）

> 临时规则必须展示"风险分级为临时规则，待 A 提供正式计算"的说明。

#### 3.3 风险原因文案模板

| `reason_code` | hover 文案模板 |
|---------------|----------------|
| `wind_speed_drop` | `{timeRange} 风速骤降，预测波动加大` |
| `wide_confidence_band` | `{timeRange} 置信区间扩大，预测不确定性高` |
| `weather_mutation` | `{timeRange} 天气条件变化较快，预测波动加大` |
| `normal` | `{timeRange} 风险较低，预测表现平稳` |

若只有 `level` 无 `reason_code`，统一展示：

> `{timeRange} 当前风险等级：{levelText}（原因待数据补充）`

#### 3.4 渲染方式

- 使用纯 HTML/CSS 色条，不使用 ECharts。
- 颜色必须来自 `MASTER.md` token，禁止硬编码色值。
- hover 展示风险时段、风险等级和原因文案。
- 色条过窄导致 hover 困难时，点击色块也可展开说明。

### 5. 经营影响分析

#### 5.1 目标

将预测结果转化为经营建议，回答：

1. 发电量变化对可交易电量有什么影响？
2. 是否增加现货偏差风险？
3. 应该调整储能还是交易策略？

#### 5.2 影响链路生成规则

页面不得长期硬编码单一路径，需根据数据选择链路模板。

**核心输入：**

- `today.total`
- `today.tradable`
- `today.storage_available_mwh`
- `forecast[].price_day_ahead`
- 昨日实际发电量（建议字段：`generation.yesterday.actual_total`，缺失时隐藏环比判断）
- 昨日可交易电量（建议字段：`generation.yesterday.tradable`，缺失时隐藏环比判断）

**链路判断规则：**

| 条件 | 链路 | 建议方向 |
|------|------|----------|
| `today.tradable < yesterday.tradable * 0.9` | 发电下降 → 可交易电量下降 → 现货偏差风险增加 | 建议降低现货比例，优先保留调节能力 |
| `today.tradable > yesterday.tradable * 1.1` | 发电上升 → 可交易电量增加 → 交易空间扩大 | 可适度提升现货或中长期交易空间 |
| 其他 | 发电平稳 → 可交易电量稳定 → 偏差风险可控 | 建议维持当前交易与储能策略 |
| 昨日数据缺失 | 仅展示当前可交易电量、储能能力与电价趋势 | 建议以当前风险阈值判断，不输出环比结论 |

#### 5.3 建议结论文案模板

**下降场景：**

> 预计未来 24 小时可交易电量下降，现货偏差风险增加。建议降低现货交易比例，并优先保留储能调节能力，以降低偏差考核风险。

**上升场景：**

> 预计未来 24 小时可交易电量增加，交易空间扩大。建议结合日前电价走势，评估适度提升现货或中长期交易比例。

**平稳场景：**

> 预计未来 24 小时发电与可交易电量整体平稳，偏差风险可控。建议维持当前储能及交易策略，并持续关注高风险时段。

**数据不足场景：**

> 当前缺少昨日对照数据，暂无法判断经营指标环比变化。建议以当前预测区间、可交易电量与电价趋势进行保守决策。

#### 5.4 AI 卡片展示

- 使用 B 的 `ai-card.js`。
- 卡片需包含：
  - 结论标题
  - 影响链路
  - 建议动作
  - 置信度
  - 数据口径说明
- 当 `meta.level = Level 1` 时，卡片标注"模拟建议"。
- 若 `ai-card.js` 未就绪，使用普通卡片占位，但保留相同信息结构。

#### 5.5 电价参考折线图

**图表类型：** `line`

**数据：** `forecast[].price_day_ahead`

**联动规则：**

- 与主预测图共用 24H / 48H / 7D 时间尺度。
- 若 7D 因主数据不足而禁用，电价图同步禁用 7D。
- 若电价数据长度与预测数据长度不一致，以两者交集时间范围展示，并提示"电价数据时段与预测时段不完全一致"。

## 四、技术要点

### 4.1 基础规范

- 从 `template.html` 复制骨架。
- Vue 3 全局版 **Options API**。
- 禁止 `setup()`。
- 禁止 `import Vue`。
- 禁止 SFC。
- 禁绝对路径。
- 改 class 后本地执行：

```bash
bash scripts/build_tailwind.sh
```

### 4.2 数据获取

统一从 A 数据层取数：

```js
import { Data } from '../assets/js/common.js';

const gen = await Data('demo/generation');
const weather = await Data('demo/weather');
const market = await Data('demo/market');
```

**前置确认项（开发前向 E/A 确认）：**

- `Data()` 是否始终返回 Promise。
- 数据不存在时返回 `null`、空对象还是抛异常。
- 数据字段缺失时是否由 A 层提供默认值。

页面必须处理：

- `Data()` resolve 但字段缺失。
- `Data()` reject。
- 数据为空数组。
- 数字字段非法值。

### 4.3 图表调用

图表只调 `chart-view.js`：

- 主预测图：`type: 'confidence'`
- 影响因子：`type: 'pie'`
- 电价参考：`type: 'line'`

禁止直接调用 `echarts.init`。

图表容器要求：

```html
<div ref="forecastChart"></div>
```

- 容器首次渲染即存在。
- 不使用 `v-if` 延迟创建图表容器。
- 如需隐藏，使用 `v-show` 或容器内空态覆盖层。
- `mounted` 中创建图表。
- `beforeUnmount` 中 `dispose`。
- 窗口尺寸变化时调用图表 `resize`（若 `chart-view.js` 已内置则无需重复实现）。

### 4.4 计算边界

允许页面侧处理：

- 时间尺度数组截取。
- 图表数据格式转换。
- 简单显隐逻辑。

禁止页面侧处理：

- 风险等级正式计算。
- 影响因子贡献度正式计算。
- 30 天 MAPE / MAE / 覆盖率聚合。
- 经营建议的复杂统计计算。

上述统计逻辑必须由 A 层提供。

### 4.5 格式化

统一使用 A 层格式化能力：

- `formatNumber`
- `formatPercent`
- `formatMoney`

页面不重复实现金额、百分比、单位换算逻辑。

### 4.6 B 组件使用

- 可信 AI 卡片：`ai-card.js`
- 数据来源弹层：`provenance.js`

若 B 组件未就绪：

- AI 卡片降级为普通卡片。
- 溯源按钮降级为简单说明弹层。
- 不允许阻塞主流程上线。

## 七、验收标准

### 7.1 功能验收

- [ ] 页面能正确读取 `generation.json / weather.json / market.json`。
- [ ] 顶部核心数字字段展示正确，无 `undefined / null / NaN`。
- [ ] 主预测图支持 24H / 48H / 7D。
- [ ] 当 forecast 少于 168h 时，7D 按钮置灰并展示原因。
- [ ] 风险时间轴支持绿/黄/橙三档展示。
- [ ] 风险 hover 能展示时段、等级和原因文案。
- [ ] 影响因子贡献环形图展示正确，并标注"模拟"。
- [ ] 经营影响分析能根据可交易电量变化输出不同链路文案。
- [ ] Level 1 时页面与 AI 卡片均展示模拟标识。
- [ ] 模型验证在缺 30 天序列时不展示空趋势图。
- [ ] 两个经营按钮跳转路径符合项目路由规范。

### 7.2 技术验收

- [ ] 全页仅使用 Vue Options API。
- [ ] 未直接调用 `echarts.init`。
- [ ] 图表容器未使用 `v-if` 延迟创建。
- [ ] 组件销毁时正确 `dispose` 图表。
- [ ] 页面无绝对路径。
- [ ] 修改 class 后执行 `bash scripts/build_tailwind.sh` 成功。
- [ ] 数据加载失败时页面不白屏。
- [ ] 控制台无未捕获 Promise 错误。

### 7.3 数据与口径验收

- [ ] 所有模拟数据均有"模拟"标注。
- [ ] 所有百分比展示统一走 `formatPercent`。
- [ ] 风险分级临时规则来自配置常量，未硬编码散落组件中。
- [ ] 影响因子贡献示例值与实际 A 返回值可无缝替换。
- [ ] 电价图与主预测图时间尺度保持一致。
- [ ] 数据更新时间展示与 `meta.updated` 一致。
