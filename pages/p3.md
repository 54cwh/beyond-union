### 2. 能源优化时间轴（核心图）

**图表类型：** `timeline`（多系列折线 + 充放电标记）

**4 个功率系列（量纲统一为 MW）：**

| 系列 | 数据字段 |
|------|----------|
| 风电出力 | `generation.forecast[].wind_power`（前 48h）|
| 光伏出力 | `generation.forecast[].pv_power`（前 48h）|
| 储能功率 | `storage.schedule[].storage_power`（正=充电，负=放电）|

- `labels` = `storage.schedule[].time` 取 `HH:00`
- **电价不入主时间轴**：市场价格单独一张 `line` 小图（见下），数据 `market.day_ahead[].price`（前 48h，与 `forecast[].price_day_ahead` 同源）

**充放电节点（从 `storage_power` 正负切换推导，不写死）：**

| 节点 | 判定 | 类型 |
|------|------|------|
| 11:00 开始充电 | `storage_power` 由 ≤0 → 正 | `charge` |
| 13:00 停止充电 | `storage_power` 由 正 → ≤0 | `charge` |
| 17:00 开始放电 | `storage_power` 由 ≥0 → 负 | `discharge` |
| 19:00 停止放电 | `storage_power` 由 负 → ≥0 | `discharge` |

> 需求示例（11:20/14:10/17:50/20:40）为分钟级示意；**实际数据为整点**，节点时间以数据推导为准，`timeline` 的 `marks[].time` 须命中整点 label（如 `"11:00"`）。
> 标记颜色由 `chart-view.js` 内置（charge 绿 / discharge 红），页面不硬编码。
> 时间尺度切换时，marks 同步过滤到当前档位的时间范围内。

**时间尺度：** 24H / 48H 两档切换；无 7D（储能调度仅 48h）。

| 方案 | 说明 |
|------|------|
| 方案 A 基准运行 | 不启用储能优化 |
| 方案 B 削峰填谷 | 峰谷套利优先 |
| 方案 C 新能源消纳优先 | 减少弃风弃光 |
| 方案 D 收益最大化 | 市场收益优先 |
| **方案 E AI 综合推荐** | 多目标综合（**高亮推荐**）|

**对比指标（7 项）与口径：**

| 指标 | 口径 |
|------|------|
| 预计收益 | 万元（当日口径）|
| 弃电率 | 弃电量 / 理论发电量（%）|
| 峰谷差 | **统计窗口内并网出力最大值 − 最小值（MW）** |
| 储能循环次数 | 日内充放电循环数（次）|
| SOC 终值 | 调度结束时 SOC（%）|

**⚠️ 数据缺口与配置化示例值**（5×7，标注"模拟"；**方案 E 的 SOC 终值/循环次数从 `storage.schedule` 实读**：SOC 终值 20%、循环 1 次，与调度数据一致）：

| 方案 | 预计收益 | 弃电率 | 峰谷差 | 循环次数 | SOC终值 | 偏差风险 | 运行风险 |
|------|---------|--------|--------|---------|---------|---------|---------|
| A 基准运行 | 4.85 万 | 8.2% | 121.4 MW | 0 | 64%（不动储能）| 高 | 低 |
| B 削峰填谷 | 5.02 万 | 5.6% | 96.8 MW | 1 | 20% | 中 | 低 |
| C 消纳优先 | 4.96 万 | 1.8% | 88.3 MW | 1 | 35% | 中 | 低 |
| D 收益最大化 | **5.35 万** | 6.4% | 105.2 MW | **2** | 20% | **高** | **高** |
| **E AI 综合推荐** | 5.21 万 | 2.1% | 82.6 MW | **1（schedule 实读）** | **20%（schedule 实读）** | **低** | **低** |

### 4. AI 推荐（可信 AI 卡片）

- 组件：B 的 `ai-card.js`
- **推荐方案 E**，5 条理由（**已与数据自洽**，标注"模拟建议"）：
  1. 午间光伏出力高（11:00–14:00 光伏 25–32 MW），充电消纳富余电量、减少弃光
  2. 晚峰价格预计上涨（17:00–20:00 电价 477–586 元/MWh，19:00 为全天峰值 586.2），17:00–18:00 放电套利
  3. 午间充电后 SOC 达上限 90%，下午满电待命应对晚峰
  4. 当前 SOC 64% 满足调度要求，充放空间充足
  5. 每日循环控制在 1 次以内，保护电池寿命（当前 SOH 95%）
- 效果量化（内联示例值，标注"模拟"）：预计收益 **+0.36 万元**（vs 基准 4.85 万）、弃电率 **-6.1 个百分点**（8.2% → 2.1%）、偏差成本 **-12.5%**
- 置信度 + 模型版本（ai-card 八要素结构，同 p2）

**充放电节点推导（页面侧允许的展示映射，非统计计算）：**

```js
// schedule[].time → "HH:00" 须命中 labels；marks 按当前档位过滤
function deriveMarks(schedule, hours) {
  const marks = [];
  for (let i = 1; i < Math.min(schedule.length, hours); i++) {
    const prev = schedule[i - 1].storage_power, cur = schedule[i].storage_power;
    const t = schedule[i].time.slice(11, 16);
    if (prev <= 0 && cur > 0) marks.push({ time: t, label: '开始充电', type: 'charge' });
    if (prev > 0 && cur <= 0) marks.push({ time: t, label: '停止充电', type: 'charge' });
    if (prev >= 0 && cur < 0) marks.push({ time: t, label: '开始放电', type: 'discharge' });
    if (prev < 0 && cur >= 0) marks.push({ time: t, label: '停止放电', type: 'discharge' });
  }
  return marks;
}
```

> 节点推导是"正负切换"的展示映射；若 A 希望统一口径，可向 A 提 `deriveChargeMarks(schedule)` 入计算层。

### 4.4 计算边界

允许页面侧：时间尺度截取、节点推导（正负切换）、`Math.max` 取峰值电价、图表数据格式转换、方案 E 的 SOC 终值/循环次数从 schedule 直读。

禁止页面侧：弃电率/偏差风险等经营指标计算、四方案的收益/风险测算（需 A 计算层提供）。

### 4.5 格式化 / B 组件

- 统一 `formatNumber / formatPercent / formatMoney`（A 计算层）
- AI 卡片 `ai-card.js`、溯源 `provenance.js`（B 组件，未就绪则降级占位）

## 九、结论

本页围绕"多方案比较 + 模型推演 + 效果量化"设计，核心是**能源优化时间轴（timeline + 充放电标记）与模型约束可解释**。

经设计审核修正：① 峰值电价以实测 586.2 元/MWh（19:00 晚峰）为准；② AI 推荐理由与数据自洽（午间光伏消纳 + 晚峰放电套利，不再声称"12–14 点电价低"）；③ 电价拆出独立小图，避免量纲混轴压扁功率曲线；④ 四方案数值表配置化、逻辑自洽（D 收益最高但风险高、E 风险调整后最优），方案 E 的 SOC 终值/循环次数实读 `schedule`（20% / 1 次）。

主要数据缺口仍是**四方案对比数据**（P1）与 **SOC 口径确认**（P1），均不阻塞开发；A 补齐后只换数据源。
